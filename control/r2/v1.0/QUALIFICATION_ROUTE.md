# R2 Qualification Strategy Adjudication v1.0

CANDIDATE / NOT ACCEPTED / NOT AUTHORIZED FOR FORMAL EXECUTION

**DECISION-R2-01 — Adopt New Qualification Route。待 Terry 裁決。**

R2 MUST 使用另行分配的新 qualification identity。Run ID、authorization、B/E/G、manifest、controller、CMS purpose、lease、transcript、evidence root、消耗狀態與 A5 acceptance MUST 按新身分分離。新身分 MUST 引用已接受的原 protocol 與 preregistration bytes。技術遷移本身不得改變科學規則或推論。

| 路徑 | 治理代價 |
|---|---|
| R2 新身分，建議採用 | 舊授權與新鏈各有唯一定位。舊 root、票據和 GO 不具新鏈權限。需新 ID、獨立授權及當次 gate |
| R1 沿用 QUAL-002 | 原授權已綁舊 environment／manifest／runner／M4。須另建同 ID 的 supersession、排他性、防重放、consumption 與失敗復原規範，並另經審查。現行合約沒有該路徑 |

政策批准 MAY 先於新 ID 與正式部署。G-POLICY MUST 保持兩個 qualification HOLD。正式身分僅於另行授權後分配，文件使用 R2_QUALIFICATION_ID_PROPOSED。
